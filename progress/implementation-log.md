## Phase 1: Reliable TCP Discovery Engine
- **Status**: COMPLETE (Awaiting User Review / Approval for Phase 2)
- **Implemented Features**:
  - Asynchronous TCP connect scanner (`AsyncTCPScanner`) using `asyncio.open_connection` with proper socket cleanup.
  - Resource protection: Bounded concurrency ceiling via `asyncio.Semaphore` and rate limiting via `AsyncTokenBucketRateLimiter`.
  - Non-bypassable scope authorization engine (`ScopeManager`): allowlist model supporting IPv4/IPv6 single addresses, CIDRs, RFC 1123 hostnames, and port ranges.
  - Scope boundaries: Default denial for public internet addresses, SSRF guard blocking cloud metadata IPs (`169.254.169.254`, `fd00:ec2::254`).
  - DNS resolution with pinning (`DNSResolver`): forward resolution validating every resolved address against scope, pinning IP to prevent DNS rebinding (TOCTOU).
  - Granular port state classification: `OPEN`, `CLOSED`, `TIMEOUT`, `FILTERED`, `UNREACHABLE`, `ERROR`, `NOT_SCANNED` (strictly distinguishing timeouts from filtered states).
  - Telemetry: Real-time progress callback emitting `ScanProgress` and structured summary `ScanSummary`.
  - Typer CLI with Rich terminal formatting (`scan`, `validate-scope`, `version`), confirmation boundary guard, and structured JSON output.

## Phase 2: Service Discovery & Protocol Fingerprinting
- **Status**: COMPLETE (Awaiting User Review / Approval for Phase 3)
- **Implemented Features**:
  - Modular protocol fingerprinting probes:
    - `HTTPProbe`: minimal RFC 9112 HEAD/GET request parsing of status line, `Server`, and `X-Powered-By` headers; detects HTTPS redirects.
    - `TLSProbe`: SSL/TLS certificate metadata extraction (subject CN, issuer CN, validity dates, SANs, protocol version, cipher suite, expired/self-signed detection) via non-intrusive handshake.
    - `SSHProbe`: RFC 4253 protocol banner extraction (OpenSSH, dropbear, libssh, OS comments, candidate CPE generation).
    - `SMTPProbe`: RFC 5321 MTA greeting banner parser (Postfix, Exim, Sendmail, Exchange).
    - `FTPProbe`: RFC 959 FTP daemon greeting banner parser (vsftpd, ProFTPD, Pure-FTPd).
    - `DatabaseProbe`: Safe listener identification for Redis (RESP `PING`), MySQL/MariaDB (initial server handshake packet), and PostgreSQL (`SSLRequest`).
  - Central `ServiceDetector` orchestrator with port-prioritized probe execution and evidence-calibrated confidence scoring (`HIGH`, `MEDIUM`, `LOW`, `UNKNOWN`).
  - Safe banner sanitization (`sanitize_banner` and `safe_close_writer`) to prevent terminal escape injection, log pollution, and resource leaks.
  - Optional `NmapAdapter`:
    - Sandboxed subprocess execution (`shell=False`) with conservative service arguments (`-sT -sV --version-light`).
    - Execution duration limits and 10 MB stdout buffer bounding.
    - Hardened XML parsing via `defusedxml` protecting against XXE injection and entity expansion bombs.
    - Normalization of Nmap XML into unified `ServiceFingerprint` models.
  - Enhanced Typer CLI with `--fingerprint / --no-fingerprint` and `--use-nmap` options, rendering Service, Product, Version, Confidence, and Latency in Rich tables.

## Phase 4: Rule-based Exposure Assessment Engine
- **Status**: COMPLETE (Awaiting User Review / Approval for Phase 5)
- **Implemented Features**:
  - `ExposureEngine`: Declarative evaluation engine matching discovered services, open ports, protocol banners, and TLS configurations against structured exposure rules.
  - Core Built-in Rulebook (`BUILTIN_RULES`):
    - Cleartext services: Telnet (`EXP-CLEARTEXT-TELNET`), FTP (`EXP-CLEARTEXT-FTP`), HTTP (`EXP-CLEARTEXT-HTTP`).
    - Database exposures: Redis (`EXP-DB-REDIS`), MySQL (`EXP-DB-MYSQL`), PostgreSQL (`EXP-DB-POSTGRES`), MongoDB (`EXP-DB-MONGODB`), Elasticsearch (`EXP-DB-ELASTIC`).
    - Insecure management consoles: SSH (`EXP-MGMT-SSH`), Docker daemon TCP API (`EXP-MGMT-DOCKER`), Kubernetes control plane (`EXP-MGMT-K8S`), VNC (`EXP-MGMT-VNC`), RDP (`EXP-MGMT-RDP`).
    - Cryptographic & TLS: Expired certificate (`EXP-TLS-EXPIRED`), Self-signed certificate (`EXP-TLS-SELFSIGNED`), Legacy protocol negotiation (`EXP-TLS-LEGACY`).
    - Information disclosures: Software & OS banner leakage (`EXP-INFO-BANNER`).
  - Custom YAML Rule Loader (`custom_rules.py`):
    - Strict validation with Pydantic (`ExposureRuleDefinition`).
    - Safe parsing with `yaml.safe_load`, 1 MB file size boundary, 500-character regex pattern limits, and ReDoS compilation checks.
    - Directory scanning (`load_rules_from_directory`) with non-terminating warning reporting.
  - Relational Finding Persistence & Lifecycle:
    - Automated deduplication per `(assessment_id, asset_id, service_id, rule_id)`.
    - Lifecycle states: `INFORMATIONAL`, `POTENTIAL_EXPOSURE`, `POTENTIAL_VULNERABILITY`, `CONFIRMED`, `FALSE_POSITIVE`, `ACCEPTED_RISK`, `NEEDS_REVIEW`.
    - Extended `AssetRepository` with `list_findings`, `get_finding` (with prefix lookup), and `update_finding_state`.
  - CLI Commands:
    - `reconforge scan`: Automatically assesses open ports and prints an exposures table.
    - `reconforge assess <assessment_id> [--rules-dir <path>]`: Evaluates rules against historical assessments.
    - `reconforge findings list [--assessment-id] [--severity] [--state]`: Tabular listing with colored severity badges.
    - `reconforge findings show <finding_id>`: Detailed panel with evidence JSON and remediation playbook.
    - `reconforge findings update <finding_id> <new_state>`: Update finding state.
    - `reconforge rules list`: Displays registered rules and trigger criteria.
    - `reconforge rules validate <file>`: Validates user YAML rule files.

## Phase 5: Vulnerability Intelligence & CVE Correlation Engine
- **Status**: COMPLETE (Awaiting User Review / Approval for Phase 6)
- **Implemented Features**:
  - NIST IR 7695 CPE 2.3 parser and serializer (`CPE`): supports CPE 2.3 format (`cpe:2.3:a:vendor:product:version:...`), legacy CPE 2.2 URI format, automatic component sanitization, and automated service attribute mapping for major services.
  - Semantic Version Matching Engine (`version_matcher.py`):
    - PEP 440 parsing and loose version comparator for non-standard software versions (`8.9p1`, `2.4.49`, `10.2p1`, etc.).
    - Strict boundary validation against NVD criteria (`versionStartIncluding`, `versionStartExcluding`, `versionEndIncluding`, `versionEndExcluding`, `exactVersion`).
    - Distro backport detection: recognizes Debian, Ubuntu, RHEL, CentOS, Amazon Linux, and SUSE packaging patterns.
  - Curated Built-in CVE Dataset (`builtin_cves.py`):
    - High-profile network service CVEs: regreSSHion (`CVE-2024-6387`), Terrapin (`CVE-2023-48795`), OpenSSH user enumeration (`CVE-2018-15473`), Apache traversal & RCE (`CVE-2021-41773`, `CVE-2021-42013`), Redis sandbox escape (`CVE-2022-0543`), vsftpd backdoor (`CVE-2011-2523`), Log4Shell (`CVE-2021-44228`).
    - Complete metadata with CVSS v3 score, vector, CWEs, affected CPEs, version criteria, advisory URLs, and CISA KEV listing flags.
  - Local SQLite Vulnerability Cache (`VulnerabilityCache`):
    - Stores CVE records in `cve_cache` table with indexed lookup by CVE ID and cached timestamp.
    - Automatic seeding with curated built-in intelligence.
    - Multi-factor search: free-text query, CPE product, minimum CVSS score, severity level, and CISA KEV filter.
  - Asynchronous NIST NVD Client (`AsyncNVDClient`):
    - Queries NIST NVD REST API 2.0 with token-bucket rate limiter (5 req/30s unauthenticated, 50 req/30s authenticated).
    - Exponential backoff with jitter on HTTP 429/503.
    - Security-hardened HTTP fetching: async thread execution, 15-second timeout, and 5 MB maximum response size limit.
    - Transparent offline cache fallback on network failure or offline mode.
  - Vulnerability Correlator (`VulnerabilityCorrelator`):
    - Calibrated confidence rating: `STRONG_CANDIDATE`, `MANUAL_VERIFICATION_REQUIRED` (distro backports), `POSSIBLE_MATCH`, `INSUFFICIENT_EVIDENCE`.
    - Both vendor and product matching to prevent vendor-level cross-product false positives.
    - Seamless persistence of findings into relational repository with calibrated lifecycle states (`POTENTIAL_VULNERABILITY`, `NEEDS_REVIEW`, `POTENTIAL_EXPOSURE`, `INFORMATIONAL`).
  - CLI Commands (`cve_app`):
    - `reconforge cve search <query>`: Search cached intelligence.
    - `reconforge cve show <cve_id>`: Display comprehensive vulnerability metrics and references.
    - `reconforge cve list-builtin`: Tabular overview of built-in offline CVE dataset.
    - `reconforge cve correlate [--assessment-id] [--record/--no-record] [--online/--offline]`: Correlate assessment services against CVE intelligence.
    - `reconforge scan --correlate-cves`: Integrated discovery, exposure assessment, and CVE correlation in a single workflow.
